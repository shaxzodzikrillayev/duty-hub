# Duty Hub 5 «Г»

Система управления дежурствами класса 5 «Г»: ученики, староста и куратор работают
с одним графиком, но видят разные части системы.

**Стек:** Node.js + Express + TypeScript · SQLite (`node:sqlite`, без нативных зависимостей) ·
React 18 + Vite + TypeScript + Tailwind · JWT в httpOnly-cookie · bcrypt · CSRF double-submit.

---

## Быстрый старт

```bash
npm install                 # ставит зависимости server и client
cp .env.example .env        # Windows: copy .env.example .env
npm run db:reset            # создаёт пустую БД + аккаунт куратора
npm run dev                 # сервер :4000 и клиент :5173
```

Открыть **http://localhost:5173**.

### Единственный готовый аккаунт

| Роль      | Логин     | Пароль         |
| --------- | --------- | -------------- |
| 👩‍🏫 Куратор | `curator` | `Curator12345` |

Учеников, старосту и график в базе нет — их добавляете вы сами:

1. **Куратор** заходит на страницу «Класс» и добавляет учеников (кнопка «+ Добавить ученик»);
2. **Староста** регистрируется с секретным кодом на странице «Регистрация» → роль «Староста»;
3. **Староста** назначает дежурных на странице «График» и ставит отметки 🟢🔴🟡🔵 каждый день.

Куратор может добавить аккаунт староста напрямую: «Класс» → «+ Добавить ученик» → роль «Староста» (секретный код не нужен, куратор и так администратор).

### Смена пароля

Кнопка **🔑 Пароль** в меню профиля (десктоп — внизу бокового меню, мобильный — в шапке):
текущий пароль → новый → повтор. Смена попадает в журнал изменений, пароль нигде не логируется.

## Переменные окружения (`.env`)

| Переменная       | Назначение                                                |
| ---------------- | --------------------------------------------------------- |
| `MONITOR_SECRET` | секретный код регистрации **старосты** (`Nulufar6789`)     |
| `CURATOR_SECRET` | секретный код регистрации **куратора** (задайте свой)      |
| `JWT_SECRET`     | ключ подписи сессий, держите в тайне                      |
| `JWT_TTL`        | время жизни сессии                                        |
| `PORT`           | порт API (по умолчанию 4000)                              |
| `ALLOWED_ORIGINS`| разрешённые Origin через запятую (для Vite: `:5173`)      |
| `DATABASE_PATH`  | путь к файлу SQLite                                       |
| `SEED_CURATOR_PASSWORD` | пароль аккаунта куратора при заполнении базы (`Curator12345`) |
| `SEED_CURATOR_FIRST_NAME` / `SEED_CURATOR_LAST_NAME` | ФИО куратора при заполнении базы |

Секретные коды **никогда не попадают в браузер**: они живут только в `.env`
на сервере и проверяются в `server/src/routes/auth.routes.ts`.

## Роли и права

| Возможность                                   | 👨‍🎓 Ученик | 👑 Староста | 👩‍🏫 Куратор |
| --------------------------------------------- | :--------: | :---------: | :---------: |
| Своё дежурство, статистика, история             |     ✅     |      ✅      |      ✅     |
| Список класса и общий график (чтение)          |     ✅     |      ✅      |      ✅     |
| Отмечать статусы, создавать/удалять назначения  |     ❌     |      ✅      |      ✅     |
| Массовое назначение и генерация месяца         |     ❌     |      ✅      |      ✅     |
| Журнал изменений                               |     ❌     |      ✅      |      ✅     |
| Добавлять учеников                             |     ❌     |      ✅      |      ✅     |
| Редактировать/удалять профили, роли, пароли    |     ❌     |      ❌      |      ✅     |

Права проверяются **исключительно на сервере** (`server/src/middleware/auth.ts`):
роль берётся из подписанного JWT и сверяется с записью в БД. Клиент может скрыть
кнопку, но запрос с чужой сессией получит `403`, а прямой переход на `/stats`
или `/journal` — редирект обратно на `/`.

### Статусы дежурства

| Статус     | Смысл                        |
| ---------- | ---------------------------- |
| 🟢 `DONE`  | дежурил                      |
| 🔴 `MISSED` | не дежурил                   |
| 🟡 `SICK`  | болел                        |
| 🔵 `REPLACED` | замена (обязателен заменяющий) |
| ⏳ `ASSIGNED` | назначен, отметка ещё не выставлена |
| ⚪ —        | не назначен (виртуальный статус, в БД не хранится) |

## Безопасность

* пароли — только `bcrypt` (10–12 раундов), наружу не отдаются никогда;
* сессия — JWT в `httpOnly` cookie, устанавливается флаг `Secure` в production;
* CSRF — double submit cookie + заголовок `X-CSRF-Token` плюс проверка `Origin`;
* все изменяющие запросы проходят через rate limit, лимит тела 64 КБ;
* `helmet`, проверка входных данных через `zod`, секреты сравниваются в постоянном времени;
* смена роли, отключение или удаление пользователя немедленно завершает сессию
  (роль сверяется с БД на каждом запросе);
* пароль никогда не логируется, в журнале изменений фиксируется кто, когда и что изменил.

## Схема данных

```sql
users (id, first_name, last_name, username UNIQUE, password_hash, role, position, is_active, created_at, updated_at)
duties (id, date, user_id, status, replacement_user_id, comment, created_by, updated_by, created_at, updated_at,
        UNIQUE(date, user_id))
audit_log (id, actor_id, actor_name, actor_role, action, entity_type, entity_id, summary, details, created_at)
```

Учебная неделя 6-дневная: понедельник — суббота, воскресенье сервер не принимает.

## Развёртывание на Vercel (serverless)

`vercel.json` + папка `api/` превращают Express в Vercel Functions: все `/api/*` идут в `api/index.ts`, статика — `client/dist`.

**Переменные окружения (обязательно в Vercel → Settings → Environment Variables):**

| Переменная       | Обязательна | Зачем |
| ---------------- | ----------- | ----- |
| `JWT_SECRET`     | да | случайная строка **от 32 символов**, иначе сервер не стартует |
| `MONITOR_SECRET` | да | код регистрации старосты |
| `CURATOR_SECRET` | да | код регистрации куратора (должен отличаться от MONITOR_SECRET) |
| `SEED_CURATOR_PASSWORD` | нет | пароль стартового куратора (по умолчанию `Curator12345`) |
| `ALLOWED_ORIGINS` | нет | доп. домены, например `https://duty-hub.vercel.app` (same-origin работает сам) |

`DATABASE_PATH` задавать не нужно: на Vercel база автоматически создаётся в `/tmp`.



> ⚠️ Файловая БД в `/tmp` живёт только внутри одного инстанса. Vercel Functions
> не имеют постоянного хранилища, поэтому при холодном старте база создаётся заново
> (аккаунт куратора заводится автоматически). Для постоянных данных подключите
> внешнее хранилище (Turso/Postgres/Neon) через `server/src/db`.

## Развёртывание

```bash
npm run build
NODE_ENV=production JWT_SECRET=<случайная строка> npm start
```

Сервер раздаёт `client/dist` сам, cookie становятся `Secure` — сайт должен работать
по HTTPS (для локальной проверки можно оставить `NODE_ENV=development`).
